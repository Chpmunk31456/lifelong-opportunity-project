## United States — O*NET 15-1254.00
O*NET describes Web Developers as developing and implementing websites, web applications, application databases and interactive web interfaces; evaluating code structure/standards/device compatibility; optimizing performance, scalability and server-side processes; and integrating websites with other applications.

Current tasks include writing supporting code, designing/building/maintaining sites, evaluating code quality and compatibility, developing supporting databases, testing sites after changes, performing updates and maintaining current knowledge of web technologies.

### Preparation
O*NET places Web Developers in **Job Zone Three — Medium Preparation Needed**. Most occupations in this zone typically require vocational training, related work experience or an associate degree, plus meaningful on-the-job development. This is occupation-level guidance, not a universal degree rule for every vacancy.

## Canada — NOC 21234
Canada Job Bank maps Web Developer to **NOC 21234 — Web developers and programmers**.

Job Bank describes these workers as using programming languages to design, create and modify websites, analyzing user needs for content, graphics, performance and capacity, and integrating websites with other applications.

### Requirements and regulation
Current Job Bank requirements state that a bachelor's degree, usually in computer science, computer programming, web development or software engineering, **or** completion of a college program in computer science or a related field is usually required; programming experience is usually required.

Current Job Bank records identify the occupation as **not regulated in Canada**. Employer expectations can still include specific technologies, education, portfolios or certifications.

### Wages
National wages, updated November 19, 2025:

- low: **C$21.48/hour**;
- median: **C$38.46/hour**;
- high: **C$57.16/hour**.

### Outlook
Job Bank's current 2024–2033 national summary says labour demand and labour supply are expected to be broadly in line. Provincial/territorial three-year prospects vary materially; current pages range from Very limited in several large provinces to Moderate in others. The guide must direct readers to current regional outlook rather than claiming one national short-term rating.

## Colombia — CUOC 25130
OCUPACOL **CUOC 25130 — Desarrolladores Web y multimedia** is a direct match. The official group covers people who research, analyze, evaluate, design, program and modify websites, multimedia, video games and interactive applications.

Relevant web-development functions include analyzing, designing and developing internet sites; combining programming with digital/media content; evaluating technical requirements; developing and modifying interactive applications; and maintaining compatibility and functional quality.

Current profile indicators do not support manufacturing one statistically representative national Colombian Web Developer salary; the revised guide will not fabricate one.

## Professional and authority boundaries
A Web Developer should not:

- deploy directly to production without assigned authority/change process;
- place passwords, API keys, tokens or secrets in source code or public repositories;
- disable authentication/authorization controls merely to make a feature work;
- collect personal data without defined business purpose/approved handling;
- copy production customer data into local/demo environments without authorization;
- perform intrusive security testing or exploitation outside explicit authorization;
- bypass review/CI/change controls to meet a deadline;
- claim that passing tests proves an application is secure, accessible or defect-free;
- claim SEO ranking or revenue outcomes as guaranteed;
- use proprietary source code or private customer data in a public portfolio;
- treat AI-generated code as correct without review/testing.

## Security boundary
The revised guide should explain that secure web development includes defense-in-depth practices such as input validation, output encoding, parameterized database access, authentication/authorization controls, secure session handling, secrets management, dependency updates, logging and security review, while recognizing that exact controls depend on architecture and organizational policy.

NIST SSDF and OWASP references can support secure-development learning, but they do not grant authorization for penetration testing or replace employer security governance.

## Accessibility boundary
Web developers should consider semantic structure, labels, keyboard operation, visible focus, contrast, zoom/reflow, alternative text, error identification, media alternatives and screen-reader compatibility. Automated tools detect only part of accessibility problems. Passing an automated scanner does not establish legal accessibility compliance.

## Responsible AI
Policy-approved AI may assist with code explanation, drafting, refactoring, tests, synthetic data and documentation. Controls must include:

- no secrets, protected customer data, proprietary source code or unreleased information in unapproved AI tools;
- human review of generated code;
- testing and static/runtime validation as appropriate;
- dependency/license review where applicable;
- review for insecure patterns, fabricated APIs and incorrect assumptions;
- no autonomous production deployment outside governance;
- authoritative requirements and actual execution results remain the evidence source.

## Safe portfolio guidance
Use self-built, open-source, explicitly licensed or demo applications and synthetic/public data. A useful portfolio can show:

- responsive site or application;
- semantic HTML and accessibility considerations;
- API integration;
- authentication demo using safe local/test accounts;
- database CRUD with validation and parameterized queries;
- tests;
- Git history and README;
- controlled CI deployment to a demo environment;
- performance/accessibility notes;
- explicit limitations and security assumptions.

Do not expose employer source code, real customer data, credentials, internal URLs, private architecture, or vulnerabilities in systems you do not own/have permission to test.
